# SUB-CUT (Subscribe Cut)

> 구독 결제일과 무료 체험 만료일을 한눈에, 필요 없는 구독을 확인하세요!

**데모**: https://ym1678ee.github.io/Sub-Cut/
**저장소**: https://github.com/ym1678ee/Sub-Cut

## 개발 의도 및 배경

**다양한 소프트웨어의 정기 구독과 무료 체험 서비스를 자주 사용하는 학생**이 **통장 잔고 관리가 안 되는 상황**에서 **이번 달 남은 기간 동안 빠져나갈 구독료 총합과 각 서비스의 결제·만료일**을 **시각적으로 한눈에 확인**할 수 있게 한다.

기존에는 캘린더 앱이나 메모에 구독 해지 일정을 따로 적어 두었지만, 다른 일정 알림에 묻혀서 무슨 서비스를 구독 중인지, 체험 만료일이 언제인지 놓치고 의도치 않은 결제가 발생하는 문제가 있었다.

## 화면 (3개)

| 화면 | 내용 |
|---|---|
| **시작 화면** | 접속할 때마다 보이는 소개 화면. 화면 어디를 눌러도 메인으로 넘어간다. |
| **메인 화면** | 이번 달 남은 구독료, 월 단위 캘린더, 남은 결제 일정. |
| **구독 관리 화면** | 구독 등록·수정·삭제·해지. 메인의 `구독 목록 확인하기`로 들어가고 `←Home`으로 돌아온다. |

**메인 화면**
- **이번 달 남은 구독료**: 오늘부터 이번 달 말일까지 실제로 빠져나가는 금액의 합.
- **캘린더**: `‹` `›`로 이전·다음 달 이동(2000년 1월 ~ 2099년 12월). 결제일은 ●(파랑), 체험 만료일은 ◆(주황). **오늘 이전의 지난 일정은 회색**으로 남는다. 날짜를 누르면 그날의 상세가 열린다.
- **월별 총 구독료**: 캘린더 우측 하단에 보고 있는 달 전체(이미 나간 결제 포함)의 합.
- **남은 결제 일정**: 오늘 이후 일정을 날짜순으로 보여주고, D-day 칩을 긴급도에 따라 색으로 구분한다.
  - **D-DAY, D-1: 빨강** / **D-2, D-3: 노랑** / **D-4 이상: 초록**
  - 색에만 의존하지 않도록 D-day 글자를 항상 함께 표시한다.

**구독 관리 화면**
- **등록**: 정기 결제(이름, 금액, 매월/매년/매주, 결제 일자)와 무료 체험(이름, 만료일).
- **수정**: 목록에서 `수정`을 누르면 같은 폼에 값이 채워진다.
- **삭제**: 구독과 그 기록을 모두 지운다. 확인 단계를 한 번 거친다.
- **해지**: `해당 서비스를 해지하셨나요?` 확인 후 **오늘을 해지일로 기록**한다. 목록에서는 사라지지만 **오늘 이전의 기록은 달력과 월별 총액에 남는다.**

## 계산 규칙

| 항목 | 규칙 |
|---|---|
| 이번 달 남은 구독료 | 오늘(포함) ~ 말일(포함)에 도래하는 결제만 더한다. 월 환산 평균은 쓰지 않는다. |
| 매월 | 결제 일자의 **일**이 매달 돌아온다. |
| 매년 | 결제 일자의 **월·일**이 매년 돌아온다. 12로 나누지 않고 그 달에 전액을 더한다. |
| 매주 | 결제 일자에서 7일씩 더한 날짜가 결제일이다. |
| 말일 보정 | 그 달에 해당 일이 없으면 말일로 당긴다. (31일 결제 → 2월 28일/29일, 4월 30일) |
| 결제 일자 이전 | 결제 일자보다 앞선 날짜에는 결제가 없다. 결제 일자는 현재보다 과거 날짜를 입력해도 된다. |
| 무료 체험 | 만료일만 입력받는다. 만료 후 자동 결제 금액은 입력받지 않고 합계에도 넣지 않는다. 만료일은 D-day로만 표시한다. |
| 해지 | 해지일 **전까지**의 결제만 인정한다. 해지일 당일과 이후는 결제하지 않은 것으로 본다. 체험을 해지하면 이후의 만료 알림이 사라진다. |

## 실행

빌드나 설치가 필요 없다. 위 데모 링크를 열거나, 저장소의 `index.html`을 브라우저로 직접 열면 된다.

## 데이터와 개인정보

- 모든 데이터는 **이 브라우저의 `localStorage`**(키 `sub-cut:v2`)에만 저장되고 서버로 전송되지 않는다. 백엔드는 없다.
- 브라우저 데이터를 지우면 구독 정보도 사라진다. 내보내기/가져오기는 일부러 만들지 않았다.
- 저장소를 쓸 수 없는 환경(시크릿 모드 등)에서는 화면 위에 안내가 나오고, 새로고침하면 입력한 내용이 사라진다.

## 알아 둘 점 (한계)

- 지난 결제는 **실제 결제 내역이 아니라 "결제 일자와 주기에 따른 계산값"**이다. 결제 기록을 따로 저장하지 않으므로, 구독의 금액·일자를 수정하면 과거 달의 표시도 같이 바뀌고, **삭제한 구독의 지난 결제는 달력에서도 사라진다.**
- **해지한 구독은 목록에서 보이지 않고, 되돌리거나 따로 삭제할 수 없다.** 기록 계산에만 쓰인다.
- 날짜는 기기의 현재 날짜(로컬 시간) 기준이다. 자정을 넘기면 새로고침해야 "오늘"이 갱신된다.
- 달력 이동 범위는 2000년 1월 ~ 2099년 12월이다.

## 만든 방식

이 프로젝트는 "바이브 코딩 개인 프로젝트" 과제로, Claude Code와 협업해 만들었다. 의도와 AI 출력 사이의 간극을 통제하는 것이 목적이어서 다음과 같이 진행했다.

- **Phase 0 (나이브 베이스라인)**: 한 줄짜리 요구사항으로 AI에게 자율적으로 만들게 했다. 결과물은 `phase0` 태그(`7ff4471`)로 남겨 두었다. (`git show phase0:index.html`)
- **Phase 1**: AI가 임의로 채웠던 가정(스택, 총합 계산법, 체험 입력 방식, 화면 구성)을 직접 정해 [CLAUDE.md](CLAUDE.md)에 규칙으로 적었다.
- **Phase 2 (재구축)**: 기능 하나씩 "계획 → 승인 → 구현 → 실행 검증 → 커밋" 순서로 다시 만들었다. 의사결정 지점은 [docs/reflection-log.md](docs/reflection-log.md)에 기록한다.
